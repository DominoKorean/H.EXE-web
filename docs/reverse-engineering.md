# 분석 근거와 일치 범위

## 구현 경계

기본 실행 경로는 `index.html` → `src/main.ts`입니다. 640×480 화면과 그림 버퍼를 별도로
유지하고, 각 픽셀은 0~15의 팔레트 인덱스입니다. 원본 실행 코드를 브라우저에서 실행하지 않습니다.
원본은 `/reference/index.html`의 비교 도구로만 둡니다. js-dos의 설정 변경이나 래핑이 아닙니다.

## 실제 원본에서 확인한 형식

| 자료 | 해석 |
| --- | --- |
| `ICON.FNT` | 64×224. 각각 4바이트 헤더를 가진 4개의 연속 비트플레인 |
| `COLOR.FNT`, `LINE.FNT`, `HANUL.^_^` | 같은 플레인 형식. 헤더는 바이트 단위 가로 stride와 세로 높이 |
| `PULLDOWN.FNT` | 16×16 아이콘 6개, 각 130바이트. 행 안에서 높은 비트의 플레인부터 저장, 끝 2바이트 패딩 |
| `ARROW.FNT` | 플레인 형식의 16×16 이미지 8개, 각 144바이트 |
| `DRIVE.FON` | BGI 40×16 이미지 3개, 각 326바이트. 마지막 326바이트는 이미지가 아닌 패딩 |
| H.EXE 내부 로고 | 파일 오프셋 `0x196FE`에서 390바이트, BGI 32×24 |
| `HANUL.LOG` | 이름과 달리 MZ 실행 파일. 시작 화면 팔레트는 `0x1910`의 5바이트 레코드 16개 |
| `VECTOR.FNT` | 비트맵 글꼴이 아닌 MZ 실행 모듈. 현재 미구현 |

BGI 이미지의 4바이트 헤더는 `(width-1, height-1)` little endian입니다.
픽셀은 각 행 안에서 높은 비트 플레인부터 저장합니다. 플레인 FNT와 BGI의 순서를 혼동하면
아이콘 색상이 달라집니다. 이 차이를 실제 리소스 테스트로 고정했습니다.

H.EXE의 MZ 헤더는 `0x1600`바이트이며 초기 데이터 세그먼트의 파일 위치는 `0x183E0`입니다.
`tools/prepare-assets.mjs`가 원본을 읽어 글꼴 조합표, 시작 팔레트, 로고만 추출합니다.
원본 바이너리 교체 시 아래 오프셋과 테스트를 다시 확인해야 합니다.

## 한글 비트맵

각 H2 한글 글꼴은 12,224바이트이고 글리프 하나는 16×16, 32바이트입니다.
초성 19자×10벌, 중성 21자×4벌, 종성 27자×4벌로 나뉩니다.
영문 파일은 ASCII 32~127의 8×16 글리프 96개, 1,536바이트입니다.

H.EXE의 DS:`034A`, DS:`0372`, DS:`038A`에서 조합표를 읽었습니다. Unicode 완성형 한글을
초·중·종성으로 분해하고, 원본 표로 벌을 선택한 뒤 비트를 OR합니다. 일반적인 조합형 표를
그대로 가정하지 않았습니다. 기본 UI에는 이야기 한글, 그림 글쓰기에는 명조 한글을 사용합니다.
원본 실행 캡처를 640×480으로 되돌려 파일명 `WEBTEST.ART`의 글자 마스크(88, 460)를 대조했습니다.
영문 글꼴 5종 중 `H2ENG_M.FNT`만 차이가 0픽셀이었습니다. 같은 캡처에서 한글 메뉴 `하늘`과
상태 표시줄의 `화일명`은 `H2IYAGI.FNT`와 각각 0픽셀 차이였습니다.

## ART

256바이트 헤더의 확인된 필드:

| 오프셋 | 의미 |
| --- | --- |
| `0x00` | `HANUL ART IMAGE FILE V2.0`, 25바이트 다음 NUL |
| `0x59` | 압축: 0=비압축, 1=원본 RLE |
| `0x5A` | 플레인 수 4 |
| `0x5B`, `0x5D` | 가로·세로 픽셀 수, little endian 16비트 |
| `0x5F` | RGB VGA DAC 팔레트 16×3바이트, 성분 0~63 |
| `0x8F` | 압축된 각 플레인의 길이, 16비트×4 |
| `0x100` | 낮은 비트 플레인부터 이어지는 그림 데이터 |

RLE 제어 바이트의 하위 7비트가 길이입니다. 상위 비트가 켜지면 다음 바이트 반복,
꺼지면 해당 길이의 원시 바이트가 이어집니다. 동봉 파일에는 마지막 반복이 예상 플레인
크기를 최대 16바이트 초과하는 사례가 있습니다. 디코더는 제한된 여분을 허용하고 잘라냅니다.
새 파일은 비압축으로 씁니다. `ROSE/SAE/WON/NASSEH.ART`의 실제 크기는 640×704입니다.

2026-11-17 웹에서 만든 `WEBTEST.ART`(640×480, 153,856바이트, 글자 픽셀 426개)를
원본 H.EXE에서 직접 불러와 문구와 파일명 표시를 확인했습니다. 증거 화면은 로컬
`artifacts/dos-art-compatibility.jpg`에 있습니다. 이 한 사례와 자체 왕복 테스트를 구분합니다.

## PCX

제조사 바이트 10, 1비트×4플레인, 헤더의 16색 팔레트를 읽습니다. RLE와 비압축을 지원하고
행 padding을 처리합니다. 쓰기는 16색 RLE이며 stride를 짝수로 맞춥니다. 동봉
`HEEDONG1.PCX`와 13픽셀 폭 테스트를 통과했습니다. 256색·트루컬러 PCX는 지원하지 않습니다.

## 상태와 입력

- 그리기는 시작 시 스냅샷을 잡고 mouseup에서 한 번 확정합니다. Esc/pointercancel은 복원합니다.
- 이동은 위치를 확정할 때에만 원본을 지웁니다. 취소·겹치는 이동·한 번의 undo를 테스트합니다.
- 다른 팔레트의 부분 그림은 대상 팔레트의 가장 가까운 RGB로 매핑합니다.
- 파일/글꼴 비동기 읽기는 요청 번호와 대화상자 소유자를 검사해 취소 뒤 문서를 교체하지 않습니다.
- 임시 보관은 IndexedDB입니다. DB를 여는 동안 편집 내용이 달라지지 않도록 저장할 버퍼를 복사합니다.
- 미확정 드래그/문자 입력 중에는 저장을 연기하고 재시도합니다. 선택·취소 이후에도 이전 변경을 보관합니다.
- 그림 밖 회색 공간에서는 새 그리기를 시작하지 않습니다. 진행 중인 드래그만 그림 경계에 제한합니다.
- 감상 모드의 키 입력은 감상을 끝내는 용도이며 그림을 지우거나 숨겨진 대화상자를 열지 않습니다.

## 원본과 아직 일치하지 않는 부분

소개글, F1 본문, 음향 전환 알림과 인쇄 선택지는 H.EXE의 조합형 문자열에서 옮겼습니다.
F1 하단의 266K는 동봉 DOS 환경의 시작 직후 표시값입니다. 시계의 모래시계는 TIME.FNT의 세 프레임을 사용합니다.
인쇄 설정은 8핀·24핀·레이저 기종과 DPI를 구분합니다. 출력에는 원본에 있는 4×4 표와 휘도 가중치를 사용하고,
크기와 흑백 점 배열을 적용한 그림을 브라우저에 전달합니다. 실제 프린터 드라이버 출력과 점 단위 대조는 남아 있습니다.
Chrome·PDF 안내, PNG 저장, 문서 붙여넣기와 웹 오류 메시지는 편집기 캔버스 바깥의 HTML UI에서 표시합니다.

**완전한 동작 호환 및 픽셀 단위 동일성은 아직 달성하지 않았습니다.**

1. 벡터 글꼴 모듈의 실행 코드와 데이터는 아직 재구현하지 않았습니다.
2. 원본의 글자 종류는 비트맵/벡터 하위 메뉴입니다. 글자 모양은 한글/영문 글꼴과 진하게,
   외곽선, 그림자, 밑줄, 어두운 음영, 밝은 음영, 흐리게, 거꾸로, 보통모양 메뉴 및 미리보기입니다.
   현재 웹에는 글꼴·배율·진하게를 선택하는 통합 창이 있으며 나머지 효과와 원본 하위 메뉴는 미구현입니다.
3. 원본의 선·원·타원·입체 상자·붓·분무기 알고리즘과 옵션의 모든 조합을 픽셀 비교하지 않았습니다.
   현재 독립 래스터 알고리즘으로 동작하며 원본과 차이가 있을 수 있습니다.
4. 시작 화면, 기본 배치, 아이콘, 로고, 파일 창, 하늘/화일 메뉴 간격·구분선은 관찰을 반영했습니다.
   그 밖의 창, 커서, 스크롤 손잡이 크기, 메뉴 복귀 규칙은 추가 대조가 필요합니다.
5. 문서부르기는 웹 문자 입력창으로 대체했고 DOS 드라이브/디렉터리는 예제 및 로컬 파일 선택기로
   연결합니다. DOS 명령 실행은 제공하지 않습니다. 인쇄·전체 화면은 브라우저 기능을 사용합니다.
6. 음향은 짧은 Web Audio 사각파로 구현했으며 원본 PC 스피커의 전체 효과 시퀀스는 분석 전입니다.
7. Windows IME의 실제 조합 후보 선택과 모든 단축키 충돌, PCX를 DOS로 다시 여는 경로,
   다중 탭 동시 편집, 접근성 포커스 순환은 추가 검증이 필요합니다.

다음 대조는 글자 종류/모양 하위 메뉴와 효과, 벡터 모듈, 도형 출력 픽셀 차이 순으로 진행합니다.
완료 여부는 테스트 개수만으로 판단하지 않고 이 목록의 실제 비교 결과로 판단합니다.
